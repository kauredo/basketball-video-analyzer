# November 2026 audit: app

Scope: the desktop app and the feedback worker. The website has its own record in `docs/audit-2026-11.md` in the website repo.

## 1. Summary

Basketball Video Analyzer is a free, AGPL desktop app for tagging game film, cutting clips and drawing on them. One active coach drives most releases by email. The audit found data-loss bugs around relinking and cancelled cuts, loose input checks on IPC handlers, and an Electron runtime past end of life. The bugs and checks are fixed, and the zip export, scouting PDF, Vimeo import and Intel Mac and arm64 Linux builds shipped afterward. What is left is the Electron 28 to 45 upgrade (plan 041), the session format v3 work (plan 042) and one small cleanup (plan 043). `main` is 18 commits ahead of the 1.13.0 release.

## 2. Shipped from the audit

- Data safety: relink keeps clips and drawings, a failed or cancelled cut removes its partial files, cancel is reported as cancel, error codes reach the UI, category export sanitises folder names (#57, #64). A cancel between thumbnail and encode no longer lets the cut finish (#57).
- Input checks: `cut-video-clip`, project creation, relink and `play-clip` validate paths and clip input; `updateCategory` allowlists its columns; dead `get-clips-by-category` IPC removed (#57). The media path cache clears on delete and relink (#64).
- Dependencies: three unused resize packages and `uuid` removed (in the audit's first app PR), lockfile security fixes (#58), Electron Forge 8 packaging (#61).
- CI and release: Linux jobs pinned to `ubuntu-24.04` because rpm 6 breaks the RPM maker (#59); the release workflow checks the tag against `package.json` and runs the tests first (#63); Intel Mac and arm64 Linux builds, with a manual run that builds without publishing (#69).
- Features from the audit's ideas: Vimeo links, cancel, and the file path taken from yt-dlp (#66); translated menus and update dialogs, and no 6-hourly modal (#65); Ko-fi button on the thank-you note after export (#67); zip export of clips and the clip list (#71, #72); shot chart PNG (#73); scouting report PDF (#74).
- Docs: `CLAUDE.md`, the stale `TODO.md` deleted, the September plan log archived (#62); plans for Electron (#60) and the session format (#70).
- Worker (separate repo): input validation and CORS on every refusal (worker #1), a deployed fix with tests (worker #3), and a rate limit plus narrower token scope (worker #4).

## 5. Decide

- Plan 041 decision D1: Electron 44 and later need macOS 13. A macOS 12 user who auto-updates into the Electron 45 build gets an app that will not launch. The plan lists the options; the README and website copy change with the answer.
- When to start 041. The audit recommends before the next feature, because every release signs and ships this runtime.

## 6. Won't do, and why

- Fast `typecheck` CI job and wider tests: CI already catches type errors, only slower, and the new tests cover the gap.
- Windows code signing through SignPath: deferred by the owner. Revisit when download stats show real Windows demand; check SignPath's free open-source program first.
- Version details in the feedback form: feedback arrives by one coach's email.
- Per-clip hover preview on the timeline: cosmetic.
- Changelog page from release notes: no demand signal.
- Download count badge: counts are too small to show.
- Weekly digest of feedback issues: a few issues a week.
- Side-by-side clip comparison and slow-mo: Kinovea territory and a large build. Reconsider only if a coach asks.
- Live tagging from a phone or tablet: a second product, which is Basketball Stats App.
- "Switch from Hudl" import or export bundle: needs Hudl's format, and nobody asked. There is also no Hudl extractor in yt-dlp.
- Trial-style landing pages: the app is free.
- Click on the court to log shot position: court position already exists.
- Import a Basketball Stats App game as clip markers: large build, no user.
- Stitched highlight reel with title cards: large build. (Sharing a project through a folder was on this line. It was built for 1.16.0 after a coach asked to work with his staff remotely: Share project, Open shared project, and a review of changes when a project comes back. Live sync stays out.)
- Paid "Pro" tier, template packs, done-for-you onboarding: the app earns nothing and has few users. Revisit only if demand shows. The AGPL, free-forever position stands.
- Outreach to coaching associations, federation or school case study, sponsored YouTube demo: no known contacts and no users to write about.
- `safeFolderName` leaving Windows reserved names (CON, NUL) and 300-character names: a failure, not a traversal.
- Per-release bump of the hardcoded fallback version on the site: only matters when the GitHub API is down.

## 8. Feature ideas not taken yet

- Shared clips by link or cloud: parked. Cloud sharing is the top gap against Hudl, but the app is local-first and free. Since 1.16.0, Share project covers handing a whole project to another coach through any folder they can reach (Drive, Dropbox, a USB stick), and the zip export still covers sending clips. Links and hosted sharing wait for a coach who needs more.
- Click-through between a Basketball Stats App game and pre-cut clips: parked until a user of both asks. The CSV and JSON export is the documented integration for now.
- Side-by-side comparison and slow-mo: parked, see section 6.
- Drawings in Sportscode XML: parked until a coach sends a file that holds them (plan 042, not in scope).
- Rule that parks most of these: features nobody asked for wait for a user. The exception is this open-source app, where improvements are welcome when they are small and tested.
